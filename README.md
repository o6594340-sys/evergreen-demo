# Event Mini-App — Evergreen Life (демо)

PWA-приложение для корпоративных событий. Демо-версия с примером программы (Стамбул) — весь контент редактируется через панель администратора.

---

## Что это такое

Это мини-сайт, который участники тура открывают на телефоне. Он работает как приложение: его можно добавить на экран (как иконку) — тогда запускается без браузера.

⚠️ Офлайн-режим (Service Worker) сейчас **временно отключён** — во время активной доработки он вызывал показ устаревшего кэша вместо свежих изменений. Включим обратно отдельным шагом, когда демо будет финализировано (см. раздел «Service Worker» в CLAUDE.md).

Два режима:
- **Участник** — открывает сайт, смотрит программу, отель, достопримечательности, контакты
- **Организатор** — заходит в панель администратора, редактирует всё содержимое

### Контент

- **Объявление** — баннер вверху (например, «Трансфер задерживается на 20 минут»)
- **Настройки события** — название, даты, Wi-Fi, контакты организатора, брендинг (цвет, лого)
- **Программа** — добавить / изменить / удалить активности по дням
- **Отель** — описание, удобства, советы
- **Достопримечательности** — добавить / изменить / удалить места
- **Рестораны** — список с описаниями
- **Кухня** — блюда, советы
- **История** — факты по разделам
- **Признание** — карточки участников: имя, город, ранг, за что отмечаем (фича под MLM-события)

### Импорт программы

Вместо ручного ввода — загрузить файл **Word / PDF / Excel / TXT** или вставить текст в специальное поле. Формат (для Excel — те же два столбца):

```
День 1 | 25 мая, понедельник
09:00 | Завтрак в ресторане отеля
11:00 | Деловая: Открытие программы
14:00 | Экскурсия: Айя-София и Голубая мечеть
19:00 | Ужин: Ресторан Firuze
```

Нажать «Разобрать программу» — программа заполнится автоматически.

Разделители `|` и `—` равнозначны. Строки с `Деловая:` попадают в деловую часть программы.

**Важно:** это структурный разбор текста по шаблону выше, а не свободное распознавание любого формата — если исходный файл сильно отличается по структуре, после загрузки текст можно поправить вручную в поле перед разбором.

## Как работают данные

Вся информация хранится в двух местах:

1. **Файл `data.js`** — данные по умолчанию (Стамбул 2026). Они показываются, если администратор ничего не менял.
2. **localStorage браузера** — изменения из панели администратора. Сайт участника автоматически берёт их, если они есть.

**Важно:** оба файла (`index.html` и `admin.html`) должны быть на одном домене. Иначе участник не увидит изменения организатора.

## Как обновить контент

1. Открыть панель администратора
2. Войти с паролем `evergreen2026`
3. Внести изменения — они сохраняются сразу
4. Участники увидят изменения при следующем открытии сайта (или после обновления страницы)

## Как адаптировать под другое событие

Есть два способа:

**Быстро — через панель:**
1. Открыть `admin.html`
2. Раздел «Данные» → «Шаблон страны» → выбрать нужное направление
3. Отредактировать под конкретный тур

**Полная замена данных — через код:**
1. Открыть файл `js/data.js`
2. Отредактировать константы `EVENT`, `HOTEL`, `DAYS`, `SIGHTS`, `CONTACTS`, `RECOGNITION` и т.д.
3. Обновить `manifest.json` — поле `name` и `short_name`
4. Обновить `<title>` в `index.html`
5. Service Worker сейчас отключён (см. предупреждение в начале файла) — версию кэша поднимать не нужно, пока не включим обратно

## Деплой (публикация в интернет)

Это статический сайт — сервер не нужен. Достаточно загрузить содержимое репозитория на любой хостинг.

**Текущий деплой:** GitHub Pages (бесплатно).

Как обновить после изменений в коде:
```
git add .
git commit -m "описание изменений"
git push
```
Через ~1 минуту GitHub Pages обновится автоматически.

**Альтернативные хостинги:**
- Beget / TimeWeb / REG.RU — дёшево, поддержка на русском
- GitHub Pages — бесплатно (используем сейчас)

## Куда движется продукт (Roadmap)

Текущая версия — **прототип** для демонстрации и первых продаж.

**Целевая модель:** SaaS-подписка для MICE-агентств из РФ.

| Что | Как |
|-----|-----|
| Каждое агентство — свой аккаунт | Firebase Auth |
| Данные агентства видны всем участникам на их телефонах | Firebase Firestore (облачная БД) |
| Фото — приватная библиотека каждого агентства | Firebase Storage |
| Менеджеры работают с разных компьютеров | синхронизация через облако |
| Тарифы | Стандарт / PRO (разный лимит событий, доступ к общей фотобиблиотеке) |

**Важное ограничение текущей версии:** данные из админки хранятся в `localStorage` — только на том устройстве, где работал администратор. Участники на своих телефонах видят данные по умолчанию из `data.js`. Это нормально для прототипа/демо, но требует переработки на Firebase перед коммерческим запуском.

**Следующий шаг:** когда появятся первые платящие клиенты → переходить на Firebase. Оценка: 2–3 недели разработки.
